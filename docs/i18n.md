# Languages

The interface speaks fifteen languages: Turkish and English (the reference pair), German, Arabic,
Spanish, French, Hindi, Indonesian, Italian, Polish, Portuguese (Brazil), Russian, Ukrainian,
Vietnamese and Simplified Chinese.

## Where a language lives

`shared/src/i18n.ts` is the register: `LOCALES`, the native name shown in pickers (`LOCALE_NAMES`),
the BCP 47 tag used for dates and numbers (`INTL_LOCALE`) and the English name put into the bot's
prompt (`LANGUAGE_NAMES`). Adding a language means one line in each of those and a catalog file; a
language missing from the register cannot be picked, stored or sent to a model.

The bot needs no prompt written per language: the English prompt says "Reply in {language}", and
the language name comes from the register.

A catalog is `app/src/i18n/<locale>.ts`, loaded only when that language is picked. The bot's own
texts live in `server/src/i18n.ts` (Turkish and English; other languages read the English one, which
names the language to answer in). The phone app merges the web catalogs with its own few keys in
`mobile/src/i18n`, and the desktop shell has its own small catalog; both fall back to English.
Arabic is the exception on the phone: React Native mirrors a layout only when it starts in
right-to-left mode, and switching that needs an app reload, so the phone shows English for Arabic
rather than Arabic text in a left-to-right layout.

## Plural forms

Languages do not share plural rules. `Intl.PluralRules` selects a category per count: Russian picks
between one, few and many, Arabic between zero, one, two, few, many and other, Chinese only other.
A message is either a string or an object holding the categories the language uses:

```ts
'chat.newMessages': {
  one: '{count} новое сообщение',
  few: '{count} новых сообщения',
  many: '{count} новых сообщений',
  other: '{count} новых сообщения',
},
```

A category the catalog does not hold falls back to `other`, so a half-finished translation shows a
count in a slightly wrong form instead of crashing or showing English. `app/src/i18n/catalogs.test.ts`
fails when a plural message lacks a category its language selects for counts 0–110, which is what
catches a Russian catalog written with only one and other.

## Right to left

Arabic is written right to left. The root element's `dir` follows the picked language in
`app/src/i18n/index.ts`, and the interface uses logical direction utilities (`ms-`/`me-`, `ps-`/`pe-`,
`start-`/`end-`, `text-start`/`text-end`, `border-s`/`border-e`, `rounded-ss`/`rounded-se`) so the
layout mirrors itself instead of being copied left-to-right. `app/src/i18n/direction.test.ts` fails
when a physical utility (`ml-`, `pr-`, `text-left`, `left-0`, `border-r`…) appears in a component.

Directional icons carry `rtl:-scale-x-100`. Arabic letters join, so the interface drops letter
spacing in right-to-left mode (`[dir='rtl'] [class*='tracking-']` in `app/src/index.css`). Inter holds
Latin, Greek and Cyrillic only, so Chinese, Arabic and Devanagari get their own font stack there;
without it the browser picks a fallback with a different weight and line height.

## Translation coverage

Catalogs start with the text a person meets first: navigation, sign-in, account, settings tabs,
search, and the chat screen with its message actions. Everything else shows in English until it is
translated, which is the designed fallback rather than a broken state.

```bash
pnpm i18n:coverage          # keys and percentage per language, plus plural problems
pnpm i18n:coverage ru       # the keys Russian still shows in English
```

Translate from the English catalog, not from Turkish: English is complete and is what the fallback
shows, so a key translated from Turkish drifts twice. Keep the placeholders (`{count}`, `{name}`, …)
byte for byte; the catalog test compares them. Translate a key in the register's own words rather
than word by word: `common.back` is a button, `chat.toBottom` is an arrow.

Catalan, Dutch, Japanese, Korean, Thai, Turkish variants and the like need no code beyond the
register and a catalog: the guard rails are language-agnostic. Machine translation is a reasonable
first draft for short labels; anything a person reads in a failure ("The turn failed: …") or acts on
("Delete this conversation?") should be read by a native speaker before the language leaves beta.
